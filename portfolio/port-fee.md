# 항만 시설 사용료 관리 시스템 — 매년 바뀌는 세율을 다루기

- **서비스** 여수광양항만공사의 GIS 기반 항만 시설 사용료 관리 시스템입니다. 지도 위 시설과 사용 업체를 연결해 사용료를 산정합니다.
- **담당** 연도별·임시 세율 관리, 업체 관리, 사용료 산정 기능을 개발하고 운영을 지원했습니다.
- **이 페이지** 첫 회사에서 15개월간 개발과 운영을 함께 맡으며 무엇을 배웠는지 적었습니다.

## 세율 — 바뀌는 값과 바뀌지 않는 규칙

| 구분 | 내용 |
| :--- | :--- |
| **도메인 특성** | 사용료 세율이 매년 개정되고, 개정 사이에 임시 세율이 별도로 적용되는 기간도 있습니다. |
| **문제** | 세율이 산정 로직 안에 있으면 개정 때마다 코드를 고치고 재배포해야 하며, 과거 기간의 사용료를 다시 계산할 수 없습니다. |
| **구조** | 연도별·임시 세율은 코드가 아니라 관리 대상 데이터로 두고, 산정 로직은 적용 시점에 해당하는 세율을 조회해 씁니다. |
| **담당** | 그 세율을 등록·수정하는 관리 기능과, 세율을 적용받는 업체 관리 기능을 개발했습니다. |

- **여기서 배운 것** **바뀌는 값은 데이터로, 바뀌지 않는 규칙은 코드로 분리해야 한다**는 것을 처음 배웠습니다. 이후 개방DB API관리에서 조회 API 자체를 메타데이터로 옮긴 것도 같은 판단의 연장입니다.

## 운영 — 월 1회 현장 방문

- **점검** 매월 현장을 방문해 서버 상태를 점검했습니다. 원격 접근이 제한된 환경이라 정기 방문이 유일한 확인 수단이었습니다.
- **대응** 담당자 문의와 개선 요청을 직접 받아 반영했습니다. 사용자와 개발자 사이에 중간 단계가 없어, 요청이 실제로 무엇을 해결하려는 것인지 그 자리에서 확인할 수 있었습니다.

## 한계

- **기록이 없습니다** 첫 회사 프로젝트라 장애 원인 분석이나 개선 전후 지표를 문서로 남기지 않았습니다. 이 페이지에 숫자를 적지 않은 이유입니다.
- **테스트가 없었습니다** 자동 테스트 없이 수동 확인에 의존했습니다. 세율처럼 기간에 따라 결과가 갈리는 로직일수록 테스트가 필요하다는 것은 이후 프로젝트에서 알았습니다.
