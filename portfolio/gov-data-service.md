# 정부 공문서 AI 조회 서비스 — 폐쇄망에서 HWP를 파싱하기

- **서비스** 행정안전부 시범 사업으로 납품된 공문서 AI 학습데이터 조회 서비스입니다.
- **담당** 파일 파싱 우회 통로를 설계하고 연동 파이프라인을 개발했습니다.
- **공개** [공공데이터포털 오픈API](https://www.data.go.kr/data/15125451/openapi.do)로 서비스되고 있습니다.

![폐쇄망 브릿지 아키텍처 — Java가 ProcessBuilder로 로컬 Python 가상환경을 서브프로세스 호출](/assets/images/portfolio/gov-bridge.svg)

## 트러블슈팅 — 외부 통신이 막힌 곳에서 파싱 자동화하기

| 구분 | 내용 |
| :--- | :--- |
| **제약** | 폐쇄망이라 외부 SaaS 호출이 불가능했습니다. |
| **원인** | HWP 파싱을 담당하던 기존 Python 코드의 버전을 폐쇄망에서 쓸 수 없어 그대로 옮길 수 없었습니다. |
| **조치** | Python 스크립트와 가상환경을 Java 서버 로컬에 다시 갖추고, 두 실행 환경을 네트워크가 아닌 같은 서버 안의 서브프로세스로 연결했습니다. |
| **결과** | 파일 입력부터 저장까지 수동 개입 없는 하나의 처리 흐름을 만들어 시범 사업 납품을 완수했습니다. |

- **연결 방식** 기존 Java(Spring MVC) 서버는 유지한 채 `ProcessBuilder`로 가상환경의 Python 실행 파일을 호출했습니다.
- **데이터 흐름** Java가 입력 파일을 전달하고, 파싱 결과를 표준 출력으로 받아 MariaDB에 저장합니다.

**한계 — 서브프로세스 방식의 비용으로 세 가지가 보강 과제로 남았습니다.**

- **타임아웃·강제 종료 정책** 실행이 길어지거나 종료되지 않는 경우를 다루지 못했습니다.
- **실행 개수 제한과 작업 큐** 동시 처리 시 프로세스 수와 메모리가 늘어나는 것을 제어하지 못했습니다.
- **오류 처리 기준** Python 표준 오류·종료 코드·부분 파싱 결과를 구분하지 못했습니다.
- **다시 한다면** 위 세 가지를 초기 설계에 포함하는 것부터 시작하겠습니다.
