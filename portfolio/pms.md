# 공정 관리 솔루션(PMS) — 라벨링 작업을 멈추지 않게 하는 운영

- **서비스** 기간별 작업자 최대 100명이 AI 학습데이터 라벨링(3D 포인트 클라우드·2D 이미지·PDF)을 원격으로 수행합니다.
- **담당** Java REST API와 관리 페이지를 개발하고, 프로젝트별 툴 커스터마이징과 배포·장애 대응을 맡았습니다.

## 저장 유실 — 무엇을 포기하고 무엇을 택했나 {#save}

{% include diagrams/pms-save-decision.svg %}

근본 조치를 알고도 택하지 않았습니다. **운영 중인 시스템에서는 옳은 조치와 지금 할 수 있는 조치가 다르고, 그 간극을 기록으로 남기는 것까지가 조치라고 봤습니다.**

### 하나의 증상, 세 개의 원인

| # | 원인 |
| :--- | :--- |
| 1 | 자동 라벨링으로 불어난 결과가 **로드된 전체 프레임의 모든 객체를 요청 하나로** 전송하는 오픈소스 저장 구조와 맞물려, 서버 저장 처리에 도달하기 전에 끊겼습니다. |
| 2 | 객체 단위 INSERT를 **요청 전체 트랜잭션 없이 건별 커밋** — 중간에 끊기면 앞부분만 남습니다. |
| 3 | 저장 없이 창을 닫는 경로가 열려 있었습니다. |

![자동 라벨링과 저장 단위가 맞물린 지점](/assets/images/portfolio/pms-auto-save.svg)

- **자동 라벨링** 한 프레임에서 객체를 지정하면 폴더 내 나머지 프레임에 같은 객체를 자동 생성합니다. 작업 효율의 핵심이자, 클릭 한 번에 객체가 폭증하는 지점입니다.
- **함께 넣은 것** 파일 이동 시점 자동 저장과 창 닫기 확인 안내로 미저장 종료 경로를 막았습니다.
- **재발 대비** 증상·원인·코드 위치·조치 순서를 오류 문서로 남겼습니다.

## 3D 중복 — 같은 증상, 다른 경로 {#duplicate}

같은 객체가 두 번 저장된 것처럼 보였지만, 저장이 두 번 실행된 것이 아니었습니다.

| 구분 | 내용 |
| :--- | :--- |
| **원인 1** | 유니크 키에 객체의 클래스·순서 번호까지 포함돼, 값이 바뀌면 갱신이 아니라 새 행으로 들어갔습니다. |
| **원인 2** | 2D 경로에 있는 기존 행 삭제 처리가 **3D 경로에만 누락**돼 이전 행이 잔존했습니다. |
| **찾은 방법** | 재현 조건을 좁힌 뒤 두 저장 경로를 나란히 놓고 비교했습니다. |

**배운 것** — 증상이 같아 보여도 원인 경로는 다를 수 있습니다. 여기서는 경로 비교가 로그 추적보다 빨랐습니다.

## 운영 — 자동화하지 않기로 한 것 {#ops}

| 항목 | 선택 | 이유 |
| :--- | :--- | :--- |
| 빌드 | GitLab CI 자동 | 소스가 이미 GitLab에 있어 관리 지점을 늘리지 않았습니다. |
| **배포 실행** | **수동 승인** | 작업자 전원의 작업 종료 후에만 배포할 수 있고, 배포 직후 동작 확인도 사람이 해야 했습니다. 자동 배포로 시점이 심야에 잡히면 확인할 사람이 없습니다. |
| 배포 전 점검 | 체크리스트로 고정 | 포트·방화벽·컨테이너 연결 중 하나만 어긋나면 전원 접속 불가인데, 그 설정이 문서가 아니라 담당자 기억에 있었습니다. |

- **인계** 화면별 PDF 매뉴얼과 서비스 내 매뉴얼 버튼을 만들고, 분기별 신규 담당자 시연과 팀별 서버 세팅 인계를 진행했습니다. 문의를 받으면 그 항목을 매뉴얼에 추가했습니다.
- **결과** 사용 문의가 초기 월평균 20건에서 1년 후 월 1~2건으로 줄었습니다.
- **한계** 100명 이하 규모라 배포 지표·자동 롤백·중앙 모니터링 없이 로그 확인 → 수정 → 재배포로 대응했습니다. 배포 소요 시간과 장애 복구 시간은 측정하지 않아, 개선을 숫자로 말할 수 없습니다.
