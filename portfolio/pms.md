# 공정 관리 솔루션(PMS) — 라벨링 작업을 멈추지 않게 하는 운영

- **서비스** 기간별 작업자 최대 100명이 AI 학습데이터 라벨링(3D 포인트 클라우드·2D 이미지·PDF)을 원격으로 수행합니다.
- **담당** Java REST API와 관리 페이지를 개발하고, 프로젝트별 툴 커스터마이징과 배포·장애 대응을 맡았습니다.
- **이 페이지** 업무 흐름은 아래 그림 한 장으로 갈음하고, 나머지는 실제로 겪은 장애 두 건을 기록했습니다.

![PMS 업무 흐름 — 매니저 배분, 작업자 라벨링, 검수 반려 루프, 검수 통과분만 JSON 납품](/assets/images/portfolio/pms-workflow.svg)

## 트러블슈팅 1 — "앞부분만 저장되고 뒤가 사라졌어요"

| 구분 | 내용 |
| :--- | :--- |
| **증상** | 문의가 가장 많았던 항목으로, 뒷부분 파일이 저장에 실패하고 저장 없이 창을 닫아 작업분이 유실됐습니다. |
| **원인 1** | 자동 라벨링으로 불어난 결과가 한 요청에 실려 서버의 저장 처리에 도달하지 못했습니다. |
| **원인 2** | 요청 전체를 감싸는 트랜잭션 없이 INSERT를 건별로 커밋해, 도중에 실패하면 앞부분만 남았습니다. |
| **조치** | 저장을 프레임 단위로 분할하고, 파일 이동 시점 저장과 창 닫기 확인 안내를 추가했습니다. |
| **결과** | 요청 크기가 폴더 전체에 비례하지 않게 되어 유실 발생 자체가 줄었습니다. |

- **자동 라벨링** 한 프레임에서 객체를 지정하면 폴더 안의 나머지 프레임에서 같은 객체를 자동 생성합니다. 작업 효율의 핵심이지만 클릭 한 번에 객체가 폭증하는 지점이기도 합니다.
- **오픈소스 저장 구조** 현재 프레임이 아니라 로드된 프레임 전체의 모든 객체를 요청 하나로 전송했습니다.
- **증상의 정체** 작업자가 본 "앞은 저장, 뒤는 유실"은 부분 저장이 아니라 부분 커밋이었습니다.
- **재발 대비** 증상·원인·코드 위치·조치 순서를 오류 문서로 남겼습니다.

![자동 라벨링과 저장 단위가 맞물린 지점](/assets/images/portfolio/pms-auto-save.svg)

**한계 — 요청 하나를 한 트랜잭션으로 묶는 구조 변경은 도입하지 못했습니다.**

- **미룬 이유** 운영 중인 툴이라 저장 경로 전체를 수정하면 회귀 범위가 라벨링 작업 전체가 됩니다.
- **택한 순서** 유실을 즉시 줄이는 조치를 먼저 넣고 구조 변경은 뒤로 미뤘습니다.
- **다시 한다면** 트랜잭션 경계를 먼저 만들고 그 위에서 전송량을 줄이겠습니다. 부분 커밋은 절반만 맞는 데이터를 남겨 아예 저장되지 않은 경우보다 발견이 늦습니다.

## 트러블슈팅 2 — 같은 객체가 둘로 보이는 3D 중복

| 구분 | 내용 |
| :--- | :--- |
| **증상** | 두 번 저장된 것처럼 같은 객체가 중복 표시됐습니다. |
| **원인 1** | 유니크 키에 객체의 클래스·순서 번호까지 포함돼, 값이 달라지면 갱신이 아니라 새 행으로 들어갔습니다. |
| **원인 2** | 2D 경로에 있는 기존 행 삭제 처리가 3D 경로에는 누락돼 이전 행이 그대로 남았습니다. |
| **조치** | 두 저장 경로를 나란히 비교해 누락 지점을 찾고, 3D에도 동일한 삭제-재삽입 처리를 적용했습니다. |
| **결과** | 중복이 해소됐습니다. |

- **증상의 정체** 저장이 두 번 실행된 것이 아니라, 갱신과 삭제 중 삭제 쪽이 없어서 생긴 문제였습니다.
- **배운 것** 증상이 같아 보여도 원인 경로는 다를 수 있습니다. 재현 조건을 좁히고 두 경로를 비교하는 것이 가장 빨랐습니다.

## 운영

- **배포** GitLab CI로 이미지를 빌드하고 수동으로 배포했습니다.
- **수동으로 둔 이유** 작업자 전원의 종료 확인 후에만 배포할 수 있고, 배포 직후 동작 확인도 사람이 해야 했습니다.
- **대신 고정한 것** 배포 전 확인 항목(포트·방화벽·컨테이너 연결)을 문서로 고정해, 담당자가 바뀌어도 같은 결과가 나오게 했습니다.
- **인계** 화면별 PDF 매뉴얼과 서비스 내 매뉴얼 버튼을 만들고, 분기별 신규 담당자 시연과 팀별 서버 세팅 인계를 진행했습니다.
- **용량 제약** 납품 검수가 끝난 회차의 파일을 삭제하도록 운영 규칙으로 정했습니다.
- **한계** 100명 이하 규모라 배포 지표·자동 롤백·중앙 모니터링 없이 로그 확인 → 수정 → 재배포로 대응했습니다.
