# 1. 공정 관리 솔루션 작업 배분과 저장 안정화

**미디어그룹사람과숲 · 2022.11 ~ 2024.12 · Java, Spring Boot, MyBatis, MariaDB, JSP, JavaScript**

![PMS 업무 흐름 — 매니저 배분, 작업자 라벨링, 검수 반려, 검수 통과 데이터 납품](/assets/images/portfolio/pms-workflow.svg)

## 만든 것과 담당 범위

AI 학습데이터의 배분, 라벨링, 검수, 납품을 관리하는 웹 시스템에서 Java REST API와 관리 페이지를 개발했습니다. 3D·2D·PDF 라벨링 툴을 프로젝트에 맞게 연결하고 배포와 장애 대응도 맡았습니다.

## 문제 상황

매니저가 한 사람에게 자료를 배분한 직후 다른 사람에게 연속해서 배분하면, 첫 배분 결과가 화면에 반영되기 전에 같은 자료가 다시 선택될 수 있었습니다. 작업자별 결과 데이터는 분리되지만 동일 자료에 두 작업자가 붙어 중복 라벨링을 하고, 사용자에게는 배분 오류로 보일 수 있는 상황이었습니다.

## 원인

배분 완료 뒤 서비스 상태를 다시 읽는 순서가 빠져 있었고, 백엔드에도 같은 자료가 동일한 작업자 권한에 이미 배분됐는지 다시 확인하는 조건이 없었습니다. 화면 상태만 바로잡으면 다른 요청 경로에서 같은 문제가 반복될 수 있었습니다.

## 해결 과정

1. 배분 완료 후 목록과 선택 상태를 다시 읽도록 화면의 갱신 순서를 수정했습니다.
2. 백엔드에서 자료와 대상 사용자의 권한을 기준으로 기존 배분을 다시 확인했습니다.
3. 같은 작업자 권한에는 동일 자료를 중복 배분하지 않고, 작업 결과를 확인해야 하는 검수자에게는 같은 자료를 배분할 수 있도록 역할별 규칙을 나눴습니다.

## 결과와 확인 범위

같은 작업자 역할 사이의 중복 배분 경로를 화면과 백엔드 두 곳에서 차단하고, 작업자와 검수자가 동일 자료를 다루는 정상 업무 흐름은 유지했습니다. 당시 별도의 중복 발생 건수 지표는 남기지 않아 감소율은 적지 않습니다.

## 함께 해결한 저장 문제

저장 유실처럼 보이던 증상을 요청 크기, 객체별 건별 커밋, 재저장 시 키 충돌의 세 경로로 나눠 확인했습니다. 자동 저장이 불러온 전체 객체를 누적 전송하던 것을 선택된 객체만 보내도록 줄이고, 무조건 INSERT를 `ON DUPLICATE KEY UPDATE`로 바꿔 재저장이 반복돼도 결과가 같아지게 했습니다. 파일 이동 자동 저장과 종료 확인도 추가했습니다. 요청 단위 트랜잭션은 두지 않았습니다 — 중간 실패 시 앞서 저장된 객체까지 되돌리면 작업자의 결과가 사라지므로 부분 보존을 택했고, 그래서 멱등 저장이 짝으로 필요했습니다.

# 2. 개방DB API관리 조회 엔진

**미디어그룹사람과숲 · 2024.09 ~ 2025.01 · Java, Spring MVC, eGovFrame, MyBatis, MariaDB, JSP**

## 문제와 원인

조회 API 하나를 추가할 때 Controller, Service, DAO, SQL XML 등 파일 5~6개와 재배포가 필요했습니다. Map 기반 파라미터와 조회 로직이 API마다 복제돼 신규 인력이 확인할 위치가 많고 검증 조건이 흩어지는 구조였습니다.

## 해결과 결과

공통 조회 흐름을 메타데이터와 변환 엔진으로 모으고 업무별 컬럼과 조건을 등록 데이터로 표현했습니다. 조회 API 추가 작업을 파일 5~6개 작성에서 메타데이터 등록 1건으로 바꿔 개발 서버에 적용했습니다. 운영 반영 전 이직해 실트래픽 성능은 주장하지 않습니다.

# 3. 사내 교육 플랫폼 권한 검증

**에이아이넷 · 2020.12 ~ 2021.03 · Java, Spring Boot, Spring Security, JPA, Oracle, SSO**

## 문제와 원인

권한 처리가 화면별 분기로 흩어져 있어 메뉴 노출을 제어할 수는 있었지만 API 엔드포인트에서 역할을 공통으로 검증하는 구조가 없었습니다.

## 해결과 결과

SSO 세션 정보를 RBAC로 구조화하고 Spring Security 계층의 공통 인터셉터에서 엔드포인트 권한을 확인했습니다. 기능마다 권한 분기를 복제하지 않고 검증 지점을 한 곳으로 모았습니다. Oracle BLOB 파일 변경은 게시물 데이터와 같은 트랜잭션으로 처리했습니다.

# 개인 프로젝트로 보완한 영역

- **DelayNoMore** — 화면 버튼으로만 막혀 있던 확정 계획 수정 경로를 서버 상태 전이 규칙으로 옮기고, 동시 요청을 PostgreSQL 기반 테스트로 검증했습니다.

- **api-forge** — 회사에서 운영 검증하지 못한 메타데이터 조회 엔진을 회사 코드 없이 재구현하고, 식별자와 값 입력 검증을 H2·PostgreSQL 테스트로 확인했습니다.
