# 개방DB 관리 시스템 설계 및 프로토타입 개발

> 데이터 스키마 추상화를 통한 Generic API 엔진 설계 및 모듈화

---

## 📌 Project Overview
- **기간**: 2024.09 ~ 2025.01 (5개월)
- **기술 스택**: Java, JSP, Spring MVC, MyBatis, MariaDB, Apache Tomcat
- **핵심 역할**: 설계 기획, Generic SQL 변환 엔진 설계 및 버전 관리 로직 구현

---

## 🔍 Problem Discovery & Cause (문제 정의 및 원인 분석)
- **문제**: 신규 인력 온보딩이 빈번히 지연되었으며, 새로운 요구사항이 있을 때마다 유사한 조회 API를 반복 개발하여 개발 생산성이 지속적으로 저하되었습니다.
- **원인**: 데이터 테이블 스키마에 결합된 하드코딩 방식의 API 개발이 고착화되어 있었으며, 이로 인해 비구조화된 레거시 코드가 누적되어 유지보수 비용이 기하급수적으로 상승했습니다.

---

## 💡 Solution (해결 과정)
1. **데이터 스키마 추상화 관리 체계 수립**
   - 하드코딩된 API 엔드포인트 개발 방식을 탈피하기 위해 데이터 구조를 유연하게 메타데이터화하는 스키마 추상화 레이어를 도입했습니다.
2. **Generic API 엔진 설계 및 리플렉션 응용**
   - MyBatis의 동적 쿼리 생성 기능과 Java의 Reflection API 개념을 응용했습니다.
   - 사용자가 UI 화면에서 선택한 메타데이터(조회하려는 컬럼 및 조건) 조합 정보를 실시간으로 파싱하여 실행 가능한 SQL 문으로 자동 변환해 주는 Generic API 엔진을 구축했습니다.
3. **API 버전 관리 체계 구축**
   - 무중단 기능 확장을 위해 라우팅 버저닝 시스템을 도입하여, 기존 동작 중인 서비스에 영향(Side Effect) 없이 유연하게 기능을 개편 및 추가할 수 있도록 보장했습니다.

---

## 📈 Results (최종 성과)
- **생산성 극대화**: 신규 조회성 API 추가에 따른 추가 코드 작성이 필요 없어짐에 따라, **신규 API 개발 공수를 0건화(완전 자동화)**했습니다.
- **온보딩 비용 감소**: 하드코딩된 소스코드를 모듈식 아키텍처로 개편하여, 새로 투입된 개발 인력이 코드를 분석하고 적응하는 온보딩 기간을 **기존 대비 절반(50%)으로 단축**시켰습니다.
