# DelayNoMore <span class="badge">개인 프로젝트</span>

> "계획을 고칠 수 있다는 여지"가 미루기를 만든다고 보고, 계획을 확정하는 순간 수정·삭제 권한을 박탈하는 **잠금(Immutable Lock) 모델**을 제품으로 검증한 프로젝트입니다.
> `DelayNoMore_Release`는 이 아이디어를 **Spring Boot + React 풀스택**으로 재구현하며, 13개 릴리스에 걸쳐 **규칙과 데이터의 소유권을 프론트엔드에서 백엔드로 옮긴** 백엔드 중심의 여정입니다.

![DelayNoMore 핵심 지표](/assets/images/portfolio/delaynomore-metrics.svg)

## 콘셉트 — "계획은 신중하게, 실행은 강제로"

AI 코치가 목표·기간·가용 시간을 대화로 수집해 **하루 단위 실행 계획**을 만들고, 사용자가 확정(서약)하면 그 계획은 **완료 체크만 허용**되는 잠금 상태로 들어갑니다. 수정·삭제라는 도피로를 구조적으로 없애 미루기를 차단하는 것이 서비스의 핵심 가설입니다.

![DelayNoMore 사용자 워크 프로세스](/assets/images/portfolio/delaynomore-flow.svg)

---

## 시스템 아키텍처

프론트엔드·백엔드·AI 프록시를 **하나의 Docker 컨테이너**로 묶어 저사양 VM에서도 단순하게 배포됩니다. Spring Boot가 빌드된 React 정적 파일과 `/api/v1` REST·SSE를 함께 서빙하고, OpenRouter 키는 서버에만 보관하며, 상태는 PostgreSQL(Supabase)에 영속화됩니다.

![시스템 아키텍처](/assets/images/portfolio/delaynomore-architecture.svg)

## 버전별 진화 과정

![버전별 진화 — v0.1에서 v0.13까지](/assets/images/portfolio/delaynomore-evolution.svg)

| 단계 | 버전 | 핵심 |
| :--- | :--- | :--- |
| **MVP 데모** | v0.1 | AI 코치 슬롯필링 대화 → 하루 단위 계획 생성, mock 폴백·CI 배포 |
| **실시간·비용** | v0.2–0.3 | SSE 토큰 스트리밍, patch 전송·이력 축소로 토큰 사용량 절감 |
| **서버 보관함** | v0.4–0.5 | localStorage 탈피, 서버 보관 CRUD, "저장"의 의미를 고정(CONFIRMED)으로 재정의 |
| **실행·회고 루프** | v0.6–0.7 | 일일 회고, 미완료 이월, 변경 감사(Audit) 이력 |
| **규칙 서버 이관** | v0.8–0.9 | 잠금·진행률·이월·날짜·patch 병합을 서버가 소유·강제 |
| **개인화·영속화** | v0.10–0.12 | 주간 요약, 게스트ID 소유자 격리, PostgreSQL(Supabase) 영속화 |
| **AI 되먹임** | v0.13 | 누적 회고로 다음 계획 분량을 추천하는 피드백 루프 |
